# Integration review — October 17, 2026

## Current follow-up: vision, official references and checker transfer

The working brain is now `v1`. A background-artwork checker generated by live NVIDIA Nemotron 3.5 Super VL passed nine development measurement cases, then detected a distorted badge on a separately generated app while leaving its clean control unflagged. The candidate is fingerprinted before generating the apps, stays frozen, and evaluation makes zero model calls. Evidence identifies the newly learned probe. Run `npm run eval:fresh -- v0 v1` or use **Test checker on fresh apps** in the UI. Results: `data/fresh-transfer.json`.

Vision is connected through Crusoe using Nemotron Super VL. You.com Search/Contents retrieves official Apple/Google guidance; the host verifies page-to-image links against approved hosts, downloads/rasterizes references, records hashes, and compares observed source bytes where a probe identifies the image. Apple uses downloadable English badge artwork; Google uses a public badge example from its official page, not an asset pack. Source equivalence does not establish permission.

Crusoe accepts one image per request, so the host combines reference, app crop and page context into one labeled image. Live inference succeeds. An identical-artwork control returns `matches`; altered fixture artwork produces review leads. Those leads stay unresolved and are never injected into confirmed fix instructions. Different image bytes alone do not prove misuse.

The final live audit confirms six expected findings and separately reports two visual review leads. Evidence: `data/runs/job-2026-10-17T20-24-24-937Z/`.

TypeScript and **28 automated tests pass**, including real browser/UI/API flows, reference provenance, multimodal payload shape, source-byte matching, and rejecting a false learning claim from an unchanged brain. The isolated scripted self-test also passes; it remains separate from live learning evidence.

The original app-b/app-d examples now serve as regression cases. The promoted v1 detects **4/4 labeled issues versus v0's 1/4**, with **zero false findings** and zero unresolved observations. This also includes a fix preventing generic words such as “analytics” from counting as a vendor's name. These familiar examples are not a pristine final benchmark. Results: `data/eval/latest.json`.

Fresh transfer tests use synthetic sites, stand-in artwork and no real tracker traffic. They demonstrate the mechanism, not real-world accuracy. The live learning experiment is retained under `data/vision-transfer/`; the original weaker experiment below remains under `data/integration-review/`.

These are four small synthetic apps with stand-in badge artwork and simulated third-party traffic. They do not establish real-world accuracy.

## Corrections made during review

- Unified the app's Crusoe and You.com wrappers with the existing tested provider clients, including key aliases, bounded retry behavior, and safe error messages.
- Isolated the self-test's brain/data so it cannot reset the working brain.
- Fixed `--no-llm` leaking model calls through semantic verification.
- Added JSON/body/version validation and cross-origin rejection; bound the local server to loopback.
- Restricted simulated traffic to registered fixture app URLs. Other audit targets and browser requests undergo public URL checks; service workers and WebSockets are blocked.
- Added fresh-page reproduction for missing policy links and browser cleanup on failures.

## Remaining product gaps

- Official visual comparison currently covers the two configured English badge references; other brands/variants need approved references. Vision judgments can still be wrong.
- Learned JavaScript has static checks and a timeout, not an enforced read-only or container sandbox. Public production use needs stronger isolation.
- The backend is a local HTTP server with file storage and one active job, without production authentication or durable job recovery.
- The directory is not currently initialized as a Git repository.
